# Supercell anti-tamper — F0/F1 result (2026-10-15)

Pilot: Brawl Stars (com.supercell.laser), device 1 (iPhone 16 Pro, **iOS 27.0**), team 1 (5CV985HSCG).

## What was established
- **We can inject a dylib that loads and runs FIRST.** The re-signed `laser` binary's first
  `LC_LOAD_DYLIB` is `@executable_path/Frameworks/FridaGadget.dylib`, so whatever file sits there
  gets its initializer run before Supercell's check. Confirmed: both the Frida gadget and our own
  `RuStoreRecon.dylib` ran as the first initializer.
- **Signing the 1.27 GB instrumented IPA now works offline**, avoiding the pipeline's result-upload
  limit: `storefront-runner --sign-file --profile brawl.mobileprovision --bundle-id <ours>` in the
  runner container (profile 6141 covers device 1; no `--inject`, the dylib is baked in). ~6 min.
  Brawl Stars has 56 nested **frameworks** and **zero extensions**, so offline `--sign-file` is valid.
- **Frida gadget 17.23.3 crashes in its own constructor on iOS 27** when loaded first:
  `EXC_BREAKPOINT (SIGTRAP)` deep inside `FridaGadget.dylib` init (`callInitializer` →
  gum init), identical offsets in both `listen`+`wait` and `script` modes. So the dynamic-tracing
  path (Stalker/REPL) is unavailable on this device with this gadget.
- **The integrity check does not go through libSystem exports.** `RuStoreRecon.dylib`
  (`research/supercell/RuStoreRecon.m`, fishhook, first-loaded) rebound `csops`,
  `csops_audittoken`, `ptrace`, `syscall`, `sysctl`, `sysctlbyname`, `getppid`, `dlopen`,
  `open`, `stat`, `exit`, `abort`, `kill`, `pthread_kill` across every app-bundle image (now and
  as they load). The app logged `START/APPROOT/READY` then died with **none of the hooks firing**.
- **The kill is an uncatchable kernel SIGKILL.** Crash: `EXC_BAD_ACCESS / SIGKILL /
  KERN_PROTECTION_FAILURE at 0x123456789a00`, namespace **CODESIGNING "Invalid Page"**, empty
  backtrace — the guard computes the poison address inline and jumps to it; the CPU faults on an
  invalid page and the kernel kills the process. A `SIGSEGV/SIGBUS/SIGTRAP` handler cannot catch it.

## Conclusion (go/no-go gate)
The guard uses **inline syscalls / direct code-signature reads**, invisible to export-level hooks,
and kills via an uncatchable codesigning fault. Export-hook instrumentation (the technique the
production compat shim uses) cannot locate it. Advancing requires **instruction-level** work:
- dynamic: a working Stalker/single-stepper — blocked (frida gadget broken on iOS 27; LLDB needs a
  development-signed build + get-task-allow, which we don't have for device 1); or
- static: Ghidra deobfuscation of `laser` + `Scid.framework/Scid` to find and patch the compute
  site — large, RecaptchaEnterprise-grade obfuscation, and re-done on every game update.

**Recommendation:** stop here unless we get an iOS-16/17 test device (where the frida gadget is
likely to run, re-enabling dynamic tracing) or commit to the static RE effort. Listings 275/443/444
stay as-is. Keep this and `RuStoreRecon.m` for a future attempt.
