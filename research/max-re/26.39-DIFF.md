# MAX deployed-base (26.35.0/7127) vs 26.39.0 (Yaqin) — feature/flag diff

**Bottom line (corrected 2026-11-08):** the features the request named as "missing" (polls, file/document
sending, stories/status, web-apps, reactions, comments) are **already present in our deployed base binary**.
They are **gated behind boolean flags** driven by the oneme.ru server config, not absent from the code.
Updating the base to 26.39 is **not** what turns them on; 26.39 adds only incremental refinements.

## Inputs (authoritative — both pulled + dumped here, not the earlier RE text file)

- **Base** = our deployed MAX: artifact **952, CFBundleShortVersionString 26.35.0 (build 7127)**, bundle
  `ru.oneme.app`, pulled from prod `originals/18/18cbd9…a008.ipa`. 4433 ObjC classes / 45650 selectors,
  cryptid 0. (Identical to `objc-classes-full.txt`.) Note: an older MAX artifact (485) was genuinely
  **26.17.3 (31710)** — the version labels on these builds have been changed over time.
- **26.39** = Yaqin 1.3.0 (`MY_CUSTOM_VERSION=26.39.0`), MAX source with `OKM*/OM*`→`YAQIN*`/Swift names.
  3003 ObjC classes / 9523 selectors (much more moved to Swift — so **class/method COUNTS across the rename
  are NOT a feature signal**; only selectors, which are not renamed, are reliable).

## 1. The named features ALREADY EXIST in the base (gated)

Base binary evidence (selectors / Router entries present in 26.35.0/7127):

| Feature | Present in base | Gate (getter / server flag) |
|---|---|---|
| Create poll | `OKMRouter showPollCreateScreenWithDelayMode:…`, `makeCreatePollViewController…`, `canCreatePolls` | `canCreatePolls` (OKMChatHandler), `shouldShowPollTab` |
| Send file / document | `sendDocumentsFromURLs:`, `canShowDocumentsPicker`, `OKMRouter showDocumentPreviewForFileURL:` | `canShowDocumentsPicker` (OMChatSendoutViewModel), `isAttachmentEnabled`, `isAttachButtonEnabled` |
| Web-apps / mini-apps | `BotWebApp`, `ShowcaseWebApp*`, `webAppBiometry…` | `isWebAppEnabled` (OMComposeContainerViewModel), `isWebAppPhoneHashEnabled` |
| Stories / status | `AddStoryView`, OM/Stories classes | server key `storiesEnabled` |
| Reactions | reactions classes | `reactions-polling-enabled` / `reactionsPollingEnabled` |
| Folders | `AddToFolderHandler`, `BatchFolderAction` | `folderFiltersEnabled`, `folderNewEntitiesEnabled` |
| Music files | media/file classes | `music-files-enabled` / `musicFilesEnabled` |

These gate getters are **instance methods** (`canCreatePolls`, `isWebAppEnabled`, `canShowDocumentsPicker`,
`shouldShowPollTab`, …) and the flags are server-pushed via `OKMKVConfigService` (`configValueForKey:ofType:`,
dash-form keys like `stories-enabled`, `reactions-polling-enabled`, `music-files-enabled`) and/or the
login/PMS config. Yaqin shows the features because its account/region config returns the flags ON; our
`ru.oneme.app` clients get some returned OFF. **Both builds use the same oneme.ru backend**, so the backend
supports the features for both — only the client-visible gate differs.

### Recommended fix (matches the request: dylib, fits the original binary, no bugs)

A small patch dylib that forces the gates ON — swizzle the existing getters to return YES
(`canCreatePolls`, `isWebAppEnabled`, `isAttachmentEnabled`, `isAttachButtonEnabled`, `canShowDocumentsPicker`,
`shouldShowPollTab`) and/or hook `OKMKVConfigService -configValueForKey:ofType:` to return YES/true for the
relevant keys. This is the same pattern as the VK forced-mode patch (`vk-music-disguise-gate`) and applies
cleanly to the original binary (it only re-points existing methods). **No base update needed.** VERIFY
on-device that the backend honours each forced feature for a `ru.oneme.app` account before fleet rollout.
Next RE step to pin the exact patch: decompile `-[OKMChatHandler canCreatePolls]` and
`-[OMComposeContainerViewModel isWebAppEnabled]` to confirm each reads config (not a hard constant) — local
Ghidra DB per `MAX-RE.md`.

## 2. What 26.39 genuinely ADDS over the base (rename-stable selector delta)

1911 selectors exist in 26.39 but not the base (incremental, not the headline features). Notable:
chat **folders** build-out (`attachFolders:`, `folderChatsManager`, `folderPin`, folder integration),

(`_commentsAttachmentCapabilities`, `areCommentsNotificationsEnabled`, comments-disabled input view),

`_statusOverrideForContact:`, per-contact hide-stories, reaction double-tap. Update the base to 26.39 only if
these specific increments are wanted.
